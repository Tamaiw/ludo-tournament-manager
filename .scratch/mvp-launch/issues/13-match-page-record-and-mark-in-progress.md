# 13: Match page, mark in-progress, record result (player + manager paths)

**What to build:** A match page at `GET /matches/{id}` shows the match's participants (with names, slots, current advancing positions if any), the parent match(es), the next match, the match status, and the available actions. A player who is a participant in the match (or the manager) can mark it `in_progress` via `POST /matches/{id}/start`. The same actor can record the result via `POST /matches/{id}/record` (form: per-slot `advancing_position` select boxes; 1-indexed; validation: positions within a match are unique, positions 1..N are required where N is the match's advance count, the rest are optional). Recording a result transitions the match to `completed`, advances the winners to the next match (creating the `match_participant` row in the downstream match with the correct slot), and if this was the final match, transitions the tournament to `completed` (T15 covers force-close separately). The `ready` transition happens automatically (computed from upstream matches) — no separate endpoint. The audit log gets one `match_result_recorded` row with `before` and `after` snapshots. The bracket fragment re-fetches on WS message in T16; for now, the show page renders the bracket on every load.
